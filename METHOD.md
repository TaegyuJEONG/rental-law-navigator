# Method note — Rental Housing Law Navigator (team JTG.ai)

**Idea.** A housing rule sits on two axes: place (which jurisdiction, which buildings) and time (enacted, effective, sunset). We let a language model read the law and place each rule on those axes, and we let deterministic code answer for an address and a date. The model never decides whether a rule applies to an address.

**Module A — extraction.** The model (gpt-5.5) reads all 53 distributed corpus texts and 22 link-only pages we saved one at a time. For each rule it returns jurisdiction, category, requirement, key value, coverage tests, exemptions, penalty, legal stage, enacted, effective and sunset dates with the words they rest on, and a verbatim quote. Code rejects any record whose quote is not found in the document (130 raw records kept). A second pass clusters records that describe the same law and keeps one core rule per law, category and jurisdiction: 56 rules, plus 23 side provisions kept out of the answer set. Status is not stored. It is computed from the dates for the query day, which is what makes "as of" queries and T1 and T3 work from one rule set.

**Citations.** The quote comes from distributed corpus text whenever any source of the rule is in the corpus. For rules supported only by link-only pages, a backfill pass searches the corpus for a supporting passage and code verifies it. Result: 89.8% of `applies` answers rest on a quote found in the distributed corpus. The remainder are Jersey City, Hoboken, Newark and two Massachusetts regulations, for which the corpus has no text.

**Module B — address lookup.** Census batch geocoder → coordinates → incorporated place and county. 38 of 500 addresses have a mailing city that differs from the legal city. Coverage is tested against public facts: certificate-of-occupancy cutoffs, rolling new-construction exemptions, unit thresholds, owner-occupied exemptions. A missing fact or a building in the cutoff year gives `unknown`. Unit bounds are read from the assessor's use description when the unit field is empty. State and local interaction comes from the text: a state rule that says it yields to stricter local law is `superseded` where the local rule covers the building, and `unknown` where local coverage is unknown.

**Module C — change tracking.** The engine is run on both dates of each test. Organiser rule ids are mapped to our rules by jurisdiction, category and legal stage. T1 250 addresses, T2 90, T3 140 with 90 conflict flags, T4 110, T5 0. The ballot question and a lapsed Boston petition are recorded as failed and never reported at an address.

**Responsible design.** Every answer shows the as-of date, source document, quote, retrieval date and reasoning. Pending and failed measures are kept apart from law. Conflicts are flagged, not resolved. Every model call is in an audit log, and outputs are cached by content hash so a rerun reproduces them. The interface says "not legal advice" on every screen.

**Scaling.** A new jurisdiction needs its documents and nothing else: `./add_document.sh text.txt "City, ST"` runs the same extraction, merge and engine. Monitoring is the same pipeline on a schedule: re-fetch sources, compare hashes, re-extract changed documents, diff the affected-address sets, and send the diff to a human.

**Limits.** No official score exists for this edition, so our 12 checks are self-validation. Owner type, many unit counts and many construction years are not public, which produces 1,117 `unknown` results. The corpus has not been reviewed by counsel, and neither has our output.
